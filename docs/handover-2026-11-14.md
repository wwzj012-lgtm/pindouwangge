## 四、识图「图例锁定 + 数量锁定」功能（待用户验收）

- **需求来源**：生成型图纸格内印刷色号污染采样，但底部图例条清晰 → 图例（色号+粒数）当识别强约束。
- **设计文档**：`docs/system_design.md`（权威）。核心决策：数量平衡放 refine 链**最后一步**（防 smooth 投回）；只让 surplus；单格 ΔE>25 不可转让；未锁定路径与旧版**逐位一致**（三形态断言守护）。
- **实测能力边界**：图例色号识别 25/27=92.6%（水印压字 2 条错）；**粒数识别 5/27=18.5%**（5×8px 细字重，多方案无突破，QA 实证置信门不可靠有 8 条高置信错读）。
- **裁决（已实施）**：默认只锁色板不锁数量；数量=用户显式勾选 +「全部锁定/解锁」按钮 + Σ超格禁用 + 常驻核对提示。错配额驱动平衡会主动改写 1183 格——**不要改回默认全锁**。
- **验收基准**：`node scripts/legend-benchmark.mjs`（退出码判 pass/fail）；真值 `benchmark/water-box.legend.json`（WATER BOX 101×132 27 色）。

## 六、必读的坑（血泪教训）

1. **部署成功判定必须 grep "Deployment complete"**——`npx wrangler pages deploy 2>&1 | tail -2` 管道吞退出码，503 瞬断会静默失败。
2. **D1 并发限制 ≤6**：dashboard 6 段 Promise.all 并行是安全上限（2026-04 起 headers 到达即释放、第 7 条排队不报错）。改 SQL 段数前先数并发数。
3. **node_modules/.vite 残留 deps_temp_* 目录 + 并行 browser 全量跑会资源超时**（7 个 Chrome 争抢）：browser 测试走 `mv node_modules/.vite` 侧移流程后单跑归因；`.vite.dep9/.qa-bak/.qa-bak2/.qa-sidestep` 等备份目录待清理。
4. **后端 tsc --noEmit 有 12 个既有类型错**（community-posts/backfill test，HEAD 既有）——别误当新错。
5. **铁律：不准自动提交/部署线上**——改动留工作区，用户说"提交部署"才动。wrangler.jsonc / .tmp/ 永不提交。
6. fallback 链铁律 `unified?.cells ?? smoothed?.cells ?? shading?.cells ?? cells` 漏 shading 会静默失效；rgbToLab 有两个版本（colorUtils `(r,g,b)` / imagePipeline `([r,g,b])`）别导错。
7. 前端拉列表默认给大 limit 前先查后端校验上限（limit=200→100 的报错先例）。
