# 网格颜色识别的算法与三段可选校正

代码：`src/utils/importRecognition.ts`（几何 + 采样 + 选色）、
`src/utils/importGridCalibration.ts`（校准模型）、
`src/utils/importRecognitionReview.ts`（复核队列）、
`src/utils/importColorBalance.ts`（白平衡与曝光归一）。

## 1. 主链路

| 步骤 | 做法 |
| --- | --- |
| 几何 | 轴对齐矩形 `{originX, originY, cellWidth, cellHeight, columns, rows}`，坐标在原图像素空间。四角拖拽本质是改这个矩形，**不支持透视/旋转**。 |
| 采样 | 每格取 `[origin+(c+inset)·cw, origin+(c+1-inset)·cw]`，按像素与格子的**几何相交面积**加权（边界像素只算一半）。`fast` 模式退化为每轴 ≤8 个等面积探针。alpha=0 或 <24 直接丢弃，所以透明格落成 blank 而不是黑。 |
| 选色 | sRGB → 线性 → XYZ(D65) → Lab，对色板逐支算 ΔE2000 取最小。色板 Lab 预计算，RGB→结果按 32768 条缓存。 |
| 合成 | **先按色号分组，再比面积**。同一支豆被 JPEG 抖成多个 RGB 簇时会合并回一支。排序：面积降序 → 加权 ΔE 升序 → 色板索引升序（保证结果确定）。 |
| 分级 | `ΔE>15 或 占比<0.6` → poor；`ΔE>8 或 占比<0.8` → fair；否则 good。 |
| 复核 | 进队列：invalid、**含糊**（主次差<0.12）、**离谱**（最近色号 ΔE>12）、**孤立**（与邻域多数色号不同，≥6 票）。人工改过的格子把 `sampleRgb/distance/ratio` 置 null——人工选择不是测量值。 |

## 2. 三段校正：全部**默认关闭**

历史教训：校正本身会成为错误来源。三项都必须显式勾选，且都有"不准动"的守卫。

| 选项 | 适用 | 做法 | 守卫 |
| --- | --- | --- | --- |
| `beadPhoto` 实物照片模式 | 拍下来的成品豆板 | ① 每格按亮度裁掉最暗 15%（孔洞/缝隙阴影）与最亮 10%（反光）；② 白片归一到**色板最亮那支豆**的亮度（含曝光）；③ 选色时 ΔL 权重降到 0.55，让选色跟色相走 | 需要画面里有近中性亮区；增益限制在 [0.8, 1.3] |
| `autoColorBalance` 校正色偏 | 暖光/阴天拍摄 | 白片（近中性最亮簇）各通道中位数拉平到中性 | 增益限制 [0.88, 1.14]；同一批抽样格重算，平均 ΔE 必须下降 |
| `autoAlign` 对齐偏移 | 整张图都框歪了 | 每抽样点做 ±0.16 格 3×3 搜索，取多数派；再整幅统一补偿 | 需 75% 抽样点一致 + 平均得分 +0.14 + 整批重算后主色占比 +0.04、色差不变差 |

### 为什么放弃「灰世界」

最早的白平衡用灰世界：整幅图平均应为中性。这在拼豆题材上**系统性错**——
深蓝背景、深色衣装常占一半以上，均值本来就是蓝的，于是被算成偏蓝，
增益把红抬上去、蓝按下去，所有中性色和肤色一起变黄。

实测一张实物拼豆照（908×1047）：

```
全图均值 RGB(86, 92, 107)
灰世界增益        R1.10  G1.03  B0.89   ← 白珠(212,216,226) → (233,221,201)，即"偏黄"
白片增益（现方案）  R1.02  G1.02  B0.97   ← 几乎不动
白片 + 曝光靶子     R1.19  G1.19  B1.14   ← 提亮，色相不变
```

同一张图脸部区域：原图 (175,172,183)，灰世界校正后 R/B 由 0.96 变 1.09 —— 就是肉眼看到的发黄。

### 为什么对齐也要默认关

多格投票只看"每格自己变好了没有"，格子多时总有少数格因噪声投票；
一旦采纳，整幅网格被永久推偏，且没有任何提示。现在加了第二重门：
把整批抽样点换成候选偏移重算，整体主色占比必须 +0.04、平均色差不得变差。

## 3. 网格分辨率：比调参重要得多

用户反馈"成品照片识别不尽人意"，最后量出来的第一原因不是颜色，是**格数只有实际豆数的一半**。

同一张 908×1047 的成品照，按 44 列和 101 列各跑一遍（`beadPhoto` 开）：

| 网格 | 每格覆盖 | 平均主色占比 | 观感 |
| --- | --- | --- | --- |
| 44 × 51 | ≈ 2.3 × 2.3 颗豆 | 43% | 一团糊，脸部成白块，左下角有黑斑 |
| 101 × 116 | 1 颗豆 | 59% | 能看清发丝、眼睛、嘴唇与吊坠线 |

网格线永远均匀，所以"格数错了"从画面上看不出来——这是最坑的地方。

为此新增 `src/utils/importGridPitch.ts` + 校准区的「按豆距自动估算格数」：

- 每条扫描线取**相邻像素亮度差的绝对值**再减均值，做归一化自相关，取"第一个够强的峰"；
- 不用原始亮度（小位移永远更相似，渐变图会一路收敛到 5px）；
- 不用带符号的差分（边界两侧明暗符号随机，正负抵消后会落到周期整数倍上）；
- 有多重周期时**宁细勿粗**：报 9px（一颗豆切成 4 格）只是分辨率偏高，报 36px（四颗豆并一格）会把颜色平均掉；
- 效果：这张照片 10ms 返回 9.0px / 101×116，置信度 47%。低于 15% 时只提示、不套用。

## 4. 待核对标记：判"可能错"，不判"格子脏"

用户看到整张图变金色——那其实是**待核对标记**，不是配色。旧判据是 `dominantRatio < 0.6`，
等于把"这一格混了几种颜色"当成"这一格可能错"。手机拍的成品照每格都混着豆缘反光与孔洞，
占比天然只有 55%，于是 **5567 / 11500 = 48%** 的格子被标记，画面金成一片，标记失去意义。

改成三条"可能错"的判据，**不设数量上限**（识别准了数量自然就少，靠截断让画面好看是自欺欺人）：

| 判据 | 含义 |
| --- | --- |
| 含糊 | 主色与次色差 < 0.12，两支豆几乎打平 |
| 离谱 | 最近色号 ΔE > 12，色板里没有这个颜色 |
| 孤立 | 与周围 8 格多数色号不同（≥6 票），拼豆大面积连续，孤立异色多半是错的 |

同时把小尺寸下的标记从"整格填琥珀色"改成"1px 橙框"——填色会把这一格识别出来的颜色盖掉，
而"该不该改"恰恰要靠那个颜色判断。

### 真正让金色变少的是取样方式

实物模式下，方形窗口里四角其实是豆子之间的暗缝（约占 21% 面积），中心又是孔洞，
两者一起拖低主色占比、也把颜色拖黑。改成**只采圆豆本体**（挖掉 r<0.22 的孔、
丢掉 r>0.92 的豆缘与缝）后：

| 设置 | 平均主色占比 | 待核对格 |
| --- | ---: | ---: |
| 默认（方窗） | 47.2% | 42.4% |
| 实物模式（圆采样） | **66.3%** | **23.9%** |

另外两处也跟着改：

- **先合并"肉眼几乎一样"的色号再比面积**（ΔE<4 的组用并查集合并）：同一颗豆被拍出明暗
  条纹时，像素会分投到两支相近色号上，面积被劈成 60/35，看着就是"两个颜色打平"；
- 「含糊」要求两支候选 **ΔE ≥ 4**——221 支色卡里次优常常只是相近的另一支，选哪支画面都一样。

### 剩下的 23.9% 是照片的信息上限

实测这张图：待核对 2751 / 11500，成因是「含糊」2472（两支明显不同的颜色各占约一半）、
「离谱」511（最近色号 ΔE>12）、「孤立」84。中位 ΔE 是 7.3。

也就是说，每格 9px、JPEG 有压缩模糊时，一格里有两种颜色是**物理事实**，不是算法没调。
想继续往下压只有两条路：拍摄更近更实（每颗豆 ≥14px），或接受这些标记。

### 渲染也跟着收敛

一格只有 3~5 个屏幕像素时，整格描边会连成橙色网格，把画面糊掉。
改成画**左上角小方块**：看得出"这一片待核对得多"，又不遮颜色。≥6px 时仍是描边。

## 5. 去杂色（`smooth`，默认关）

照片识别最大的观感问题是"胡椒盐"式的孤立错格，而拼豆作品本身大面积连续。
把主色占比 < 0.75 的格子改成周围 8 格里出现最多的色号（至少 5 票），
高置信格一个都不动；替换后按同一采样色重算 ΔE 与质量等级。

实测 101 列 + 实物模式 + 去杂色：修正 924 / 11716 格（7.9%），发丝与轮廓保留，噪点明显减少。

## 6. 仍然做不到的

- **强暗角/单侧光源**：同一支豆在中心和四角能差 15% 以上亮度，等于跨了一个色阶。
  全局归一救不了，需要分区参考（未实现）。
- **JPEG 严重模糊**：相邻豆互相渗色，主色占比本身就很低，只能靠复核人工修。
- **透视/旋转**：几何仍是轴对齐矩形，手机斜拍会逐行串格。
- **浅色内容 vs 光照色偏**：只有白片信息时两者不可分。所以增益被限制在 ±12%，
  超出就放弃——宁可让用户手动改几格，也不要把整张作品改色。
