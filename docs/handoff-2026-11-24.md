### 000. 数量识别攻坚：card1 29→37/43、card3 0→45/48（2026-11-24 深夜场，用户指定「先按数量方向改」）

  3. **单位字尾裁**（`CARD_UNIT_GAP=6`，竖排路径）：数字间间隙实测 0-4px、数字↔粒 8-12px，按最后一个 ≥6px 间隙切掉尾部单位组（高度守卫：单位字至少与数字同高）。亚像素版下多数行已由宽块丢弃兜住，此规则是兜底。

### 00. 图例「白色票面条目丢失」修复：dog-girl 54→60/62 条（2026-11-24 深夜场）

### 5. 颜色识别（importRecognition.ts，实物照片模式）
- **v5 smooth 双守卫是当前线上版**：同色 4 邻≥2 是结构不许吞；跨档（色号对色号 ΔE>12）不许改。v8（色系聚合投票+曝光归一）指标赢但用户目检输，已整体回滚——**指标与目检冲突时以目检为准**。
- **改写类守卫口径铁律：色号对色号**，"采样色到目标"会被混色格骗过；拉亮放行、拉暗拦截（不对称）。
- **fallback 链**：`unified?.cells ?? smoothed?.cells ?? shading?.cells ?? cells`——漏 shading 会让 refine 静默失效但 UI 照报计数。
- 图纸色号辅助（symbolAssist，`importSymbolOCR.ts`）：底色众数+对比掩码→图内自举模板→**整串 Jaccard 匹配**（2 字符色号逐字必糊）→色板约束解码。
- L* 尺度陷阱：0-255 加权亮度≠CIE L*，混用会误判（必须 rgbToLab）。

### 6. 图例区域锁定（更早，11-14 轮次）
- 三版式全通：底部横条(water-box)/右侧竖列(yao)/右上面板块(瑶)。区域仲裁按条目数；用户框选区域（紫色框选工具）直通不做仲裁。
- 白名单自动开（命中率≥0.7 或 usable==headerCount）；自绘 CodeListbox 解决侧栏滚动弹层飞出。

## 二、注意事项（坑清单，按疼的程度排）

1. **部署必须先 build**：`wrangler pages deploy` 传的是 `dist/`，不自动构建。漏 build = "改了代码线上没变化"。
2. **全量 vitest 并发跑会假失败**（多 Chrome 抢资源，importLegend 计时敏感测试被饿死）——用 `npm run verify`（串行 `--no-file-parallelism`）或单跑可疑文件。
3. **基准回归必须用浏览器判分**（`node scripts/browser-card-test.mjs`）：数量识别依赖 DOM canvas，Node 里跑数量全是 0。
4. **sed 批量改源码后必须 grep 核验**——锚点不匹配会静默失败（已发生多次）。
5. ** vite ssrLoadModule/浏览器 evaluate 的模块坑**：page.evaluate 里 `import('react')` 裸说明符解析失败，必须经 vite 管道加载项目内文件；验证页加载真实 App 时 querySelector 会匹配到 App 元素，fixture 选择器必须限定 `#fixture-host` 作用域。
6. **布局**：CSS Grid 在 flex-1 固定高容器里默认 `align-content: stretch` 拉伸行——筛选型网格必须 `content-start`；grid 子项 `min-width:auto` 不收缩，手机溢出真凶通常是它。
7. **重写 CSS 必须整段浏览器截图复核**（丢一个 display:flex 就会竖排堆叠）。
8. **印刷票色≠豆色是物理上限**（card1 先验命中仅 33%）——先验只用于窗口约束和 ΔE≤6 的码长辅助切片。
9. **求解层禁止全局重解**：唯一性名额是全局耦合，局部翻案会连锁打翻无关行（历史教训 #1/#29/#57）。
10. **诊断脚本命名 `tmp-*`** 已进 .gitignore，不会污染 git status；但别把有长期价值的脚本叫 tmp-*。
