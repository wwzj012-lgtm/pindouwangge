# 管理端数据仪表盘重做 + 视觉统一 PRD

- 版本：v1.0 ｜ 作者：许清楚（PM）｜ 状态：待评审
- 范围：管理端「数据仪表盘」重做 + 管理端视觉规范统一（表格/筛选/弹窗/按钮/表单的视觉，不改这些页面的功能）
- 技术预设：前端 Vite + React 19 + MUI/Tailwind（管理端自有 `admin.css`）；图表库 **Recharts**；后端 Cloudflare Workers + D1（需扩展 `/api/admin/dashboard`）

## 1. 问题定义

| # | 用户原话 | 事实 | 产品判断 |
|---|---|---|---|
| 1 | 「这分析的是啥，太丑了，这没有使用开源的图表吗」 | 5 张图为手写 SVG `TrendChart`：110px 高、3 条虚线、无 Y 轴刻度/数值、无单位 | 不可读图形 = 没有分析。换 Recharts 只是手段，目的是让图可读（有刻度、有数值、有对比） |
| 2 | 「鼠标悬停还会遮挡」 | tooltip 绝对定位 `top:0`，固定贴在绘图区顶部，正好压住峰值 | 交互缺陷：提示必须避让数据点 |
| 3 | 「分析的东西有实际分析意义吗」 | 5 张图全是「每天多少个」独立面积图；`成功操作趋势` 只是操作日志条数，与图纸/发布不可比 | 这是虚荣指标堆叠：5 张同构图无法回答任何一个决策问题 |

**目标**：管理者打开仪表盘 **30 秒内**能回答 4 个问题 —— ① 今天有人在用吗、比昨天好还是差？② 用户产出内容后有没有走到社区（转化断在哪一步）？③ 我现在必须处理什么？④ 系统稳不稳？答不上来的图表一律删掉。

## 2. 分析框架（每个图/卡片 = 一个可行动的问题）

### 2.1 指标清单与精确公式

| 域 | 指标 | 公式（表.字段） | 回答的问题 → 行动 | 优先级 |
|---|---|---|---|---|
| 增长 | 今日新增用户 | `COUNT(users) WHERE created_at >= 今日0点(UTC)` | 拉新是否正常 | P0 |
| 增长 | 今日新增用户（环比） | `今日至今 / 昨日同一时刻之前的值` | 趋势判断，避免「今天还没过完」导致的假下跌 | P0 |
| 增长 | 新增创作者 | `COUNT(DISTINCT works.user_id) WHERE works.created_at ∈ 窗口` | 有多少人真的动手做了 | P0 |
| 增长 | 互动活跃用户（代理 DAU/WAU） | `COUNT(DISTINCT uid)`，uid 取并集：`works.user_id` ∪ `community_posts.author_uid` ∪ `community_likes.uid` ∪ `community_favorites.uid`（各自按窗口过滤） | 社区是否有人气 | P0（WAU 7 天）；DAU 见下 |
| 增长 | **真 DAU/WAU（本期不做）** | 需 `user_activity_logs.actor_uid`，但当前埋点写入恒为 `NULL`（见 `index.ts` 遥测写入），无法按用户去重 | 依赖埋点改造（新增登录/会话侧活跃上报），本期只做代理口径并标注 | 不做 |
| 增长 | 留存（本期不做） | 需按注册 cohort 追踪回访，`actor_uid` 为 NULL 无法归属回访用户 | 与 DAU 同源阻塞；P2 待埋点后做 7 日留存 | 不做 |
| 内容 | 图纸创建数 | `COUNT(works) WHERE created_at ∈ 窗口` | 生产端活跃度 | P0 |
| 内容 | 图纸完成**事件** | `COUNT(user_activity_logs) WHERE event_type='pattern.grid_finalized'`（备选 `pattern.saved`）。**只能当事件数，不能当去重图纸数**：同一图纸每个 revision 上报一次、`entity_id=NULL` 无法按图纸去重，故它可能大于「图纸创建数」 | 有多少次画完动作发生 | P0 |
| 内容 | 社区发布数 | `COUNT(community_posts) WHERE published_at ∈ 窗口 AND withdrawn_at IS NULL` | 供给是否上去 | P0 |
| 内容 | **发布转化率** | `社区发布数 / 图纸创建数`（同窗口）。分母=0 → 「本期无样本」；结果 >1（完成事件含修订导致）→ 显示「—（口径不可比）」，**不钳位到 100%** | 断在「做完」还是「敢发」→ 决定做引导还是做审核放宽 | P0 |
| 内容 | 漏斗三步 | 图纸创建 → **完成事件（含修订）** → 社区发布（同窗口绝对值 + 每步转化率） | 一眼看出漏在哪一步 | P0 |
| 内容 | 撤回率 | `COUNT(community_posts) WHERE withdrawn_at ∈ 窗口 / 同窗口发布数` | 内容质量/审核误伤 | P1 |
| 质量 | **错误率** | `error_events(窗口) / (user_activity_logs(窗口) + error_events(窗口))` | 稳定性是否恶化 | P0 |
| 质量 | 平均/最大耗时 | `AVG/MAX(json_extract(metadata_json,'$.durationMs'))`，仅 `json_valid` 且类型为 integer/real | 慢接口是否影响体验 | P0 |
| 质量 | 错误码 Top N | `GROUP BY error_code ORDER BY count DESC LIMIT 5`（`error_events`） | 定位最该修的一个问题 | P0 |
| 质量 | 未处理错误数 | `COUNT(error_events) WHERE resolved_at IS NULL AND occurred_at ∈ 窗口` | 是否有人在看 | P1 |
| 运营 | 待审核帖子 | `COUNT(community_post_moderation) WHERE state='pending'` | 需要动手 | P0 |
| 运营 | 待处理举报 | `COUNT(content_reports) WHERE status='open'`（与举报列表默认筛选、`adminReports.ts` 既有产品决策一致；**本期不纳入 `reviewing`**，以保证 P0-5 下钻计数一致）。另返回 `pendingReportsReviewing` 仅作副行灰字展示 | 需要动手 | P0 |
| 运营 | 兑换码可用库存 | `COUNT(vip_codes) WHERE used=0 AND delete_pending_at IS NULL`；阈值读 `system_settings['codes.low_stock_threshold']`（默认 50） | 是否会断供 | P0 |
| 对比 | 今日 vs 昨日同刻 | 所有「今日」指标同时返回昨日同一时刻值 | 环比 | P0 |
| 对比 | 近 7 天 vs 前 7 天 | `[T-6,T]` vs `[T-13,T-7]` 同指标 | 周环比 | P0 |
| 对比 | 30 天序列 | 按 `strftime('%Y-%m-%d', ts/1000,'unixepoch')` 按天分组，缺失日补 0 | 长期形态（周节律） | P0 |

**口径声明（必须显示在图表标题下方 12px 灰字，不允许静默）**
1. 错误率＝代理口径：成功只统计白名单路由（`userActivityEvents`），错误统计全部 5xx，故真实错误率 ≥ 展示值。
2. 「今日」按 UTC 0 点切分（与现有 SQL 一致），不按北京时间；需在产品内标注「UTC」。
3. 活跃用户为代理口径（见上），标题必须写「互动活跃用户（代理）」。
4. 空数据不补造：某段无数据时显示「近 N 天无新增」，不画 0 值假曲线。
5. 漏斗第二步是**完成事件数（含修订）**，非去重图纸数；任一转化率 >1 时展示「—（口径不可比）」并保留原始分子分母，不做钳位、不显示 >100%（由接口 `completionsAreEvents` 标志驱动前端呈现）。
6. 「待处理举报」只计 `status='open'`（与举报列表默认筛选一致）；`reviewing` 数量仅以副行灰字呈现，不计入首屏「待处理合计」。

**禁止的虚荣指标**：累计注册用户、累计图纸数、累计帖子数不得单独成图；只能作为「新增/活跃」卡片的副标题小字。原「成功操作趋势」删除（日志条数无决策含义），改为错误率 + 耗时趋势。

## 3. 布局（首屏优先级）

**一屏内最该看到的 4 个数字**：① 今日新增创作者（含昨日同刻环比）② 7 天发布转化率 ③ 待处理（待审核 + 待举报合计）④ 24 小时错误率。理由：分别回答「有人来吗 / 内容流转通吗 / 我要不要动手 / 系统稳吗」。

```
┌──────────────────────────────────────────────────────────────┐
│ 数据仪表盘                                  [时间范围 7/30天] [刷新]│
├──────────────────────────────────────────────────────────────┤
│ ①今日新增创作者 12 ↑+20% │ ②7天发布转化率 34% │ ③待处理 5 ● │ ④24h错误率 1.2% │
│   （副行：昨日同刻 10）   │ （副行：图纸412→发布140）│ 审核3/举报2 │   （副行：错误8/请求640）│
├──────────────────────────────────────────────────────────────┤
│ 30 天趋势（主图，高 220px）                                    │
│ 折线：新增用户 · 互动活跃用户(代理)  ｜ 柱：图纸创建            │
│ Y 轴左刻度(人) / Y 轴右刻度(个) · X 轴日期 · 图例右上           │
├───────────────────────────────┬──────────────────────────────┤
│ 内容漏斗（横条+转化率）        │ 错误率与耗时（双线，30天）      │
│ 创建 412 → 完成事件 268(65%)  │ 错误率% 折线 + 平均耗时ms 折线  │
│ （含修订）→ 发布 140 总转化 34%│ 错误码 Top5 列表（右侧）        │
├───────────────────────────────┴──────────────────────────────┤
│ 待办条：待审核 3 · 待举报 2 · 兑换码库存 42(阈值50) ← 可点击下钻  │
└──────────────────────────────────────────────────────────────┘
```

- 卡片分組：**A 决策卡（4 个数字）** → **B 趋势（主图）** → **C 转化与质量（2 列）** → **D 待办（可下钻）**。旧版 5 张同构图整块删除，不与新版并存。
- 移动端（<640px）：A 卡 2×2 网格；B 主图降为 7 天（横向滚动不利于阅读），图高 180px；C 两卡上下堆叠，漏斗改为三步竖排；D 待办三项纵向列表，每项 40px 高。桌面端 2 列在 <900px 折叠为 1 列。
- 时间范围：默认「近 7 天」；切「近 30 天」只影响 B/C/D 的窗口与时序，A 卡固定今日口径不变。

## 4. 交互规范

| 项 | 规范 |
|---|---|
| Tooltip 位置 | **禁止固定在绘图区顶部**。跟随数据点 X，垂直方向自动避让：数据点位于绘图区上半部 → 提示显示在点**下方** 12px；下半部 → 上方 12px。水平方向按容器边界钳位（左边界左对齐 / 右边界右对齐），不得溢出卡片。`pointerEvents:none`，不遮挡鼠标命中。 |
| Tooltip 内容 | 日期（12px muted）+ 指标名与值（主值 16px/600，单位小字）+ 环比（如 `较昨日同期 +2`）。多序列图一次性显示全部序列值，不逐序列切换。 |
| 图例 | 右上角、12px、色块 8×8 圆点 + 文字；可点击切换序列显隐（隐藏后 Y 轴自适应）。单序列图不显示图例。 |
| Y 轴 | 必须显示刻度与单位；刻度 3–4 档，整数对齐（人数不出现 0.5）；不给零值日留空洞（补 0 后正常参与折线）。 |
| 空态 | 分区级：一行 12px 灰字「近 N 天无新增/无错误记录」，高度 ≤24px，不渲染空坐标系。 |
| 加载态 | 首屏用等高骨架屏（占位块与真实卡片同高，避免布局跳动），不用整页 spinner；刷新时保留旧数据 + 顶部一行「正在更新…」。 |
| 错误态 | 沿用现有分段降级：单段失败只该卡片显示「数据暂不可用」，页脚 footnote 可展开真实错误文本；整接口失败才整页重试。 |
| 深色模式 | 本期默认浅色单主题（用户偏好浅色 Vercel 风）。**但所有图表颜色必须从 CSS 变量取值、禁止硬编码**；暗色 token 在 §5 已定义，暗色跟随 `prefers-color-scheme` 列为 P2。 |
| 键盘可达 | 图表容器 `tabIndex=0`，左右方向键逐日移动提示，Esc 关闭；焦点环 2px primary。 |

## 5. 视觉规范（管理端统一）

**栅格与密度**：间距只允许 4 / 8 / 12 / 16 / 20px 五档（沿用 `--admin-space-1..5`）；卡片内边距 10–12px；卡片间距 8–12px；禁止 24px 以上空白带。

**字号阶梯**（仅 5 级，新增字号需评审）：11px 辅助/时间戳 ｜ 12px 标签/表头/图注 ｜ 13–14px 正文/表格 ｜ 16–18px 卡片标题与中号数字 ｜ 22–24px 首屏 KPI 数字。全部数字用 `font-variant-numeric: tabular-nums`。

**组件尺寸**：按钮高 32px（icon 按钮 32×32）｜ 输入/筛选控件高 32px ｜ 徽标高 20px、圆角 999px ｜ 顶栏 48px ｜ 侧栏 224px ｜ 表格行高 36px（`td` 上下 7px）｜ 弹窗圆角 8px、最大宽 560px。**圆角全局只允许 8px（卡片/按钮/输入/弹窗）与 999px（徽标）两种**，权限树等现存 10px 圆角统一改回 8px。

**图表序列色（亮色，图形对象需 ≥3:1）**：① `#4f46e5` 6.29 ② `#0d9488` 3.74 ③ `#b45309` 5.02 ④ `#7c3aed` 5.70 ⑤ `#be123c` 6.29。最多 5 条序列，超过则改为小多图，不再加色。

**暗色 token（P2 预留，同一对比度门槛）**：底色 `#0f172a`、面 `#131c2b`、主文字 `#e6edf7`(15.15)、次文字 `#cbd5e1`(12.02)、muted `#94a3b8`(6.96)、primary `#818cf8`(5.98)、success `#86efac`(12.71)、warning `#fcd34d`(12.38)、danger `#fca5a5`(9.41)、图表序列 `#818cf8 / #2dd4bf / #fbbf24 / #c4b5fd / #fb7185`（均 ≥6:1）。**禁止用 `#64748b` 作暗色背景上的文字**（3.93:1 不达标）。

**状态色语义（固定，不允许自创）**：success=正常/已完成；warning=待处理/需要关注；danger=异常/失败；info=中性提示。**禁止「红涨绿跌」**——涨跌一律用 `▲/▼` 加正负号表达（涨用 primary 或 ink，跌不用红色），红绿只属于股票场景。

**表格**：行高 36px、`1px` 行分隔、表头 12px/600 灰底 `--admin-subtle`、无斑马纹（hover 行 `--admin-subtle`）、首列不截断、数字列右对齐。

**筛选**：标签在控件上方 12px；控件高 32px、`auto-fit minmax(180px,1fr)` 一行排布；搜索框最大 320px；「重置/查询」按钮与控件同基线。

**弹窗**：头/体/脚三段固定，头 `min-height:0` 可滚动、体独立滚动、脚常驻；主按钮在右、次按钮在左；移动端按钮纵向全宽（主按钮在上）。

**禁止事项（评审否决项）**：彩色渐变背景/按钮 ｜ 超过 8px 的卡片圆角（徽标除外）｜ 装饰性插图与空图占位 ｜ 无刻度无数值的装饰曲线 ｜ 纯色块堆叠的「信息图」｜ 阴影用作层级唯一手段（必须配合 1px 分隔）｜ 12px 以下文字 ｜ 硬编码颜色值（必须走变量）｜ 文案里的感叹号与营销话术。

## 6. 需求池

**P0（本次必须，缺一不可上线）**
1. 四个决策卡（今日新增创作者/7 天发布转化率/待处理合计/24h 错误率）+ 昨日同刻环比。验收：数字与手写 SQL 抽查一致；昨日同刻口径在标题下有说明；无数据时显示「—」而非 0。
2. 30 天趋势主图（Recharts，双 Y 轴、刻度+单位、图例可切换）。验收：任一点 hover 提示不覆盖该点（截图对比通过）；Y 轴有数值刻度；切换序列后轴自适应。
3. 内容漏斗三步 + 每步转化率 + 总转化率。验收：分母为 0 时显示「本期无样本」，不出现 Infinity/NaN；完成事件数 > 创建数（含修订）时，受影响转化率显示「—（口径不可比）」且不钳位到 100%，图注写明「完成事件（含修订）」。
4. 错误率 + 耗时 30 天趋势 + 错误码 Top5。验收：错误率公式与 §2.1 完全一致，页脚注明代理口径。
5. 待办条三项可下钻到对应列表并带筛选条件。验收：点击后目标页筛选条件正确、计数一致（待举报按 `status='open'` 与列表默认筛选对齐；`reviewing` 数量仅副行展示）。
6. Tooltip 避让策略全站生效（含旧图若有残留）。验收：峰值日与首末日 hover 均不遮挡、不溢出卡片。
7. 视觉统一落地为 `admin.css` 变量层改造：颜色/字号/圆角/间距 token 收敛；`--admin-faint`、`--admin-success`、`--admin-danger` 按 §5 替换。验收：axe 对比度检查 0 error；管理端各页无 10px 圆角残留。
8. 性能护栏：仪表盘首屏数据 ≤ 2 次串行往返；30 天查询不超时。验收：本地/预发 P95 < 1.5s，D1 并发连接 ≤ 6（见 §8）。包体积验收见 §8 风险表：图表独立 chunk ≤125KB gzip，AdminPage 主 chunk 零增长。

**P1（本次尽量）**
9. 时间范围切换（7/30 天）联动 B/C/D 区，A 区固定今日。验收：切换后不整页闪烁，图表平滑过渡。
10. 撤回率与未处理错误数。验收：口径文案与公式一致。
